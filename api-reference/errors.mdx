title: "Errors"
description: "HTTP status codes and the dot-coded error strings the API returns — match on the code, not the status or the human text."
---

Calibri uses conventional HTTP status codes plus a machine-readable **dot-coded**
error string in the body.

## Error body

```json
{ "errors": ["market.order.insufficient_balance"] }
```

Codes are namespaced by domain (`market.order.*`, `public.*`, `account.*`,
`identity.*`, `prediction.*`).

<Warning>
  Match on the **code**, not the HTTP status and not the human-readable text. New codes are added over time — treat an unknown code as a generic failure of its HTTP class rather than crashing on it.
</Warning>

## HTTP status codes

| Code | Reason | Description |
|---|---|---|
| 400 | Bad Request | The request is invalid |
| 401 | Unauthorized | API key, secret or HMAC signature incorrect, or the nonce is outside the accepted window |
| 403 | Forbidden | Authenticated, but not permitted to access this endpoint |
| 404 | Not Found | Invalid endpoint or resource |
| 405 | Method Not Allowed | Wrong method for the endpoint |
| 422 | Unprocessable Entity | Understood, but the data provided is incorrect |
| 429 | Too Many Requests | Rate limited — back off exponentially |
| 500 | Internal Server Error | A problem on our side |
| 503 | Service Unavailable | Scheduled maintenance — see [Status and Maintenance](/api-reference/status) |

## Trading and orders

| Code | Status | Meaning |
|---|---|---|
| `Invalid order side` / `Invalid order direction` / `Invalid order price` / `Invalid order volume` | 422 | `side` is not `yes` or `no`, `direction` is not `buy` or `sell`, the price is missing or not strictly between 0 and 1, or the volume is missing or not positive |
| `market_id must be a market id (a number or a numeric string)` | 422 | `market_id` is missing or not a numeric id |
| `market.order.create_failed` | 422 | The engine refused the order — most often not enough collateral (a buy locks stake **plus** the taker-fee reserve, unless it is post-only) or, on a sell, more shares than your `sellable_volume` |
| `market.order.tokens_settling` | 422 | A sell of shares that are still settling on-chain; they can be sold once the match confirms |
| `market.order.expired` | 400 | The order's signature expires in under 30 seconds, so a fill could not settle in time. A signature that has already expired is refused before this, with `422` `signed_order expiration is out of range` |
| `market.order.account_not_active` | 403 | Account is not in an active state |
| `market.order.kyc_required` | 403 | KYC level below the market's minimum |
| `market.order.invalid_state` | 422 | Cancel refused: the order is already terminal or fully matched |
| `market.order.not_found` | 404 | Order does not exist or is not yours |
| `public.market.doesnt_exist` | 404 | Unknown market |
| `market.market.disabled` | 422 | The market is not open for trading — not open yet, or closed |
| `market.engine.not_found` | 404 | Market data is unavailable for this market |
| `public.k_line.invalid_period` / `non_integer_period` | 400 | Bad k-line `period` |
| `prediction.event.not_found` | 404 | Unknown event slug or id |
| `authz.invalid_signature` / `authz.nonce_expired` / `authz.nonce_reused` / `authz.unexistent_apikey` / `authz.apikey_not_active` / `authz.invalid_api_key_headers` / `authz.invalid_session` | 401 | Missing or invalid credentials — see [Authentication](/api-reference/authentication) |
| `authz.invalid_permission_scope` | 403 | The API key's scope does not allow this request |
| `server.error` (`/pythia`) / `Internal server error` (`/atlas`) | 500 | Unexpected server error. On `POST /atlas/account/orders`, `/batch` and `/replace` it comes back as `502`: the matching engine failed |
| `maintenance` | 503 | Scheduled maintenance; the body carries `eta` and `message` ([Status and Maintenance](/api-reference/status)) |

A `post_only` order that would take liquidity is not refused with an error: it is accepted and then moves to state `reject`.

## Self-custody — Safe, relay, and session keys

| Code | Status | Meaning |
|---|---|---|
| `Market is not CTF-registered` | 422 | No on-chain condition exists for this market yet (`404` on `GET /account/wallet/markets/{id}`) |
| `signed_order with signature is required for non-custodial orders` | 400 | The order was posted without a `signed_order`, or without its `signature` |
| `Member safe is not settlement-ready` | 422 | Approvals outstanding — relay `safe_setup.calls` first |
| `signed_order maker is not a Safe registered to this member` / `signed_order maker must be the member safe wallet` | 422 | The `maker` is not your Safe (type `3` / type `2`) |
| `signed_order signature does not match the signer` | 422 | The signature does not verify |
| `Your trading key has expired or been revoked — approve with your passkey` | 422 | The [session key](/non-custodial/session-keys) grant has expired, or was revoked before the key placed an order. A key revoked after placing orders fails the signature check instead |
| `That order was signed by a key that cannot sign for your wallet…` | 422 | The signature is from a key that is not an owner of the Safe — including an order hash signed directly instead of the SafeMessage |
| `safe does not belong to this member` | 400 | The relayed Safe is not yours |
| `Session keys are not enabled` | 400 | Session-key trading is not available |
| `Session keys require a passkey wallet` | 400 | The member has no passkey wallet |
| `This account's wallet is a passkey wallet, so orders must be signed by it…` | 422 | A type `2` order from an account whose wallet is passkey-owned. A linked wallet is a sign-in credential; to sign orders it must be added as a [signing key](/non-custodial/signing-keys) and sign as type `3` |
| `Your passkey is no longer able to sign for this wallet…` | 422 | A signing key you added removed your passkey as an owner. Raised on the first order, withdrawal, or redemption the passkey is refused for — see [Signing keys](/non-custodial/signing-keys) |
| `A two-factor code is required to add a signing key` | 422 | `POST /account/wallet/owners` without `otp`. Only adding needs it; removing does not |
| `That two-factor code is not valid` | 422 | Wrong code, or 2FA is not enabled on the account |
| `This is your passkey. Removing it would leave your wallet signable only by the other key.` | 400 | Refused: the owner-removal endpoint will not remove your passkey. A [signing key](/non-custodial/signing-keys) can still remove it with a Safe transaction it signs |
| `This account already signs with your own wallet…` / `This account already has a self-custody wallet…` | 400 | Passkey enrolment on an account that already has a self-custody wallet. One per account |

<Note>
  Funding is sending USDC to your Safe on-chain, not an API call. A withdrawal on Polygon is a Safe transaction you sign and relay through `POST /api/v2/atlas/account/wallet/relay`, whose refusals are `422` with a `code` — see the API reference and [Funding your account](/wallet-deposits). A withdrawal to another network is priced by `GET /api/v2/atlas/account/bridge/withdraw/quote`, whose refusals are `422` with a `code` (`below_minimum`, `withdrawals_disabled`, `chain_inactive`, `receive_not_positive`, `no_safe`, `no_wallet`, `destination_is_safe`, `destination_not_linked_wallet`) — see the API reference.
</Note>

## Identity and sessions

| Code | Status | Meaning |
|---|---|---|
| `identity.session.invalid_params` | 401 | Wrong email or password |
| `identity.session.missing_otp` | 401 | 2FA code required |
| `identity.session.invalid_otp` | 401 | 2FA code incorrect |
| `identity.session.otp_rate_limited` | 429 | Too many 2FA attempts |
| `identity.wallet.already_linked` | 409 | That wallet is already linked to a different account |
| `identity.wallet.account_already_linked` | 409 | This account already has a different wallet linked |

## Rate limits

Requests are limited per route class, with stricter limits on order intake,
wallet relays, and member-intake endpoints than on public reads. Implement
exponential backoff on `429`.
