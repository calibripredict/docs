The Calibri API gives you programmatic access to everything you need to build on top of a prediction market engine — from browsing and filtering markets to placing orders, tracking positions, and streaming live price updates. Whether you're building a trading bot, a data dashboard, or a third-party integration, these endpoints cover the full lifecycle of a prediction market.

## API Surfaces

Calibri exposes four distinct API surfaces. Each serves a different purpose and runs on its own base URL.

| Name | Base URL | Description | Auth Required |
|------|----------|-------------|---------------|
| Gamma API | `https://gamma-api.calibri.com` | Market discovery and metadata | No |
| CLOB API | `https://clob.calibri.com` | Orderbook, pricing, order management | Partial (trading endpoints) |
| Data API | `https://data-api.calibri.com` | Positions, trades, analytics | No (address-based) |
| WebSocket | `wss://ws-subscriptions-clob.calibri.com/ws/` | Real-time streams | Partial |

## Request Format

For `POST` and `PUT` requests, send a JSON body and include the `Content-Type: application/json` header. Query parameters are used for filtering and pagination on `GET` requests.

```http
Content-Type: application/json
```

## Response Format

All responses return JSON. Calibri uses standard HTTP status codes to indicate the outcome of every request.

| Status Code | Meaning |
|-------------|---------|
| `200 OK` | The request succeeded. |
| `400 Bad Request` | Your request contained invalid parameters or a malformed body. |
| `401 Unauthorized` | Authentication is required or your credentials are invalid. |
| `404 Not Found` | The requested resource does not exist. |
| `429 Too Many Requests` | You have exceeded the rate limit for this endpoint. |
| `500 Internal Server Error` | Something went wrong on Calibri's end. |

## Authentication

Public endpoints — such as market discovery and price history — require no authentication. Authenticated endpoints (order placement, account management) use **L2 HMAC-SHA256 signed requests**. You include the following headers with every authenticated request:

| Header | Description |
|--------|-------------|
| `POLY_ADDRESS` | Your wallet address |
| `POLY_API_KEY` | Your API key |
| `POLY_PASSPHRASE` | Your API passphrase |
| `POLY_SIGNATURE` | HMAC-SHA256 signature of the request |
| `POLY_TIMESTAMP` | Unix timestamp of the request |

<Note>
  For full details on generating signatures and managing API keys, see the [Authentication guide](/authentication).
</Note>

## Timestamps

Calibri uses two timestamp formats depending on the endpoint:

- **Unix seconds** — used in price history responses (the `t` field) and WebSocket messages.
- **ISO 8601 strings** — used in market metadata fields such as `endDate`, `startDate`, and `closedTime`, for example `2025-11-05T00:00:00Z`.

When filtering by date in query parameters (e.g. `end_date_min`), pass ISO 8601 strings.

## Pagination

Most list endpoints use **offset-based pagination** via `limit` and `offset` query parameters.

```http
GET /markets?limit=50&offset=100
```

The default page size is `100` and the maximum is `500`. To page through results, increment `offset` by `limit` until the response returns fewer items than your `limit`.

Some endpoints also support **cursor-based pagination** via a `keyset` parameter (e.g. `GET /markets/keyset`). Cursor-based pagination is more efficient for large result sets and avoids duplicate results when new data is written between requests.

## Error Responses

When a request fails, Calibri returns a JSON object with an `error` field describing what went wrong.

```json
{
  "error": "invalid parameter: limit must not exceed 500"
}
```

Use the HTTP status code to determine the category of the error, and the `error` string to surface actionable detail in your application logs.
