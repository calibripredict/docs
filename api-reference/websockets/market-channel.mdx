The market WebSocket channel streams live order book data for any outcome token on Calibri. Once you subscribe, you receive a continuous feed of price updates, full book snapshots, last-traded prices, and market resolution events — all without authentication. This makes it ideal for building public-facing dashboards, automated quoting systems, or real-time trading interfaces.

---

## Connection

Connect to the public market channel at:

```
wss://ws-subscriptions-clob.calibri.com/ws/market
```

<Note>
  No authentication is required for the market channel. The connection is fully public — any client can connect and subscribe.
</Note>

---

## Subscribing

After opening the connection, send a subscription message to specify which outcome tokens you want to track.

```json
{
  "type": "market",
  "assets_ids": ["71321045679252212594626385532706912750332728571942532289631379312455583992563"],
  "initial_dump": true
}
```

### Subscription Fields

<ParamField body="type" type="string" required>
  Must be `"market"`. Identifies this as a market channel subscription message.
</ParamField>

<ParamField body="assets_ids" type="string[]" required>
  An array of outcome token IDs (ERC-1155 token IDs) to subscribe to. You can include multiple token IDs in a single subscription.
</ParamField>

<ParamField body="initial_dump" type="boolean">
  When `true`, the server immediately sends a full `book` snapshot for each subscribed token upon connection. Defaults to `false`. Use this to initialize your local order book state without waiting for the next delta.
</ParamField>

<Tip>
  You can subscribe to multiple tokens in a single connection by passing an array of token IDs in `assets_ids`. There is no need to open separate WebSocket connections per token — this dramatically reduces overhead when monitoring a large number of markets simultaneously.
</Tip>

## Event Types

The server pushes the following event types on the market channel. Each message is a JSON object with an `event_type` field that identifies its shape.

<AccordionGroup>

<Accordion title="book — Full Order Book Snapshot">

The `book` event delivers a complete snapshot of the order book for a token. You receive this on initial subscription (if `initial_dump` is `true`) and whenever the server emits a full refresh.

Use this event to initialize or reset your local order book state.

```json
{
  "event_type": "book",
  "asset_id": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "market": "0xConditionId...",
  "bids": [
    { "price": "0.62", "size": "500.00" },
    { "price": "0.61", "size": "1200.00" }
  ],
  "asks": [
    { "price": "0.63", "size": "800.00" },
    { "price": "0.64", "size": "2000.00" }
  ],
  "hash": "0xBookHash...",
  "timestamp": "1700000000",
  "min_order_size": "5",
  "tick_size": "0.01"
}
```

| Field | Type | Description |
|---|---|---|
| `asset_id` | string | The outcome token ID this snapshot belongs to. |
| `market` | string | The condition ID of the parent market. |
| `bids` | array | All resting buy orders as `{ price, size }` pairs, sorted descending. |
| `asks` | array | All resting sell orders as `{ price, size }` pairs, sorted ascending. |
| `hash` | string | A hash of the current book state, useful for integrity checks. |
| `timestamp` | string | Unix timestamp (seconds) of the snapshot. |
| `min_order_size` | string | Minimum order size accepted by the exchange for this token. |
| `tick_size` | string | Minimum price increment for this token. |

</Accordion>

<Accordion title="price_change — Single Price Level Delta">

The `price_change` event fires whenever a single price level in the order book changes. Apply these deltas incrementally to your local book state. A `size` of `"0"` means that price level has been removed entirely.

```json
{
  "event_type": "price_change",
  "asset_id": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "price": "0.62",
  "size": "750.00",
  "side": "BUY",
  "timestamp": "1700000042",
  "bestBid": "0.62",
  "bestAsk": "0.63"
}
```

| Field | Type | Description |
|---|---|---|
| `asset_id` | string | The outcome token ID for this update. |
| `price` | string | The price level that changed. |
| `size` | string | The new total resting size at this price level. `"0"` removes the level. |
| `side` | string | `"BUY"` or `"SELL"`. |
| `timestamp` | string | Unix timestamp (seconds) of the change. |
| `bestBid` | string | Current best bid after this update. |
| `bestAsk` | string | Current best ask after this update. |

</Accordion>

<Accordion title="last_trade_price — Last Traded Price">

The `last_trade_price` event fires after each confirmed trade, reporting the price, size, and on-chain transaction hash.

```json
{
  "event_type": "last_trade_price",
  "asset_id": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "price": "0.625",
  "timestamp": "1700000055",
  "transaction_hash": "0xTxHash..."
}
```

| Field | Type | Description |
|---|---|---|
| `asset_id` | string | The outcome token ID of the trade. |
| `price` | string | The price at which the trade executed. |
| `timestamp` | string | Unix timestamp (seconds) of the trade. |
| `transaction_hash` | string | The on-chain transaction hash for the matched trade. |

</Accordion>

<Accordion title="tick_size_change — Minimum Increment Update">

The `tick_size_change` event fires when the exchange adjusts the minimum price increment for a token. Update your order entry logic accordingly to avoid submitting orders at invalid price precision.

```json
{
  "event_type": "tick_size_change",
  "asset_id": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "new_tick_size": "0.001"
}
```

| Field | Type | Description |
|---|---|---|
| `asset_id` | string | The outcome token whose tick size changed. |
| `new_tick_size` | string | The new minimum price increment. |

</Accordion>

<Accordion title="market_resolved — Resolution Notification">

The `market_resolved` event fires when a market settles. After receiving this event, the winning outcome shares become redeemable for $1.00 of pUSD and losing shares become worthless.

```json
{
  "event_type": "market_resolved",
  "condition_id": "0xConditionId...",
  "outcome": "Yes",
  "resolvedAt": "1700010000"
}
```

| Field | Type | Description |
|---|---|---|
| `condition_id` | string | The condition ID of the resolved market. |
| `outcome` | string | The winning outcome (e.g., `"Yes"` or `"No"`). |
| `resolvedAt` | string | Unix timestamp (seconds) when the market was resolved. |

</Accordion>

</AccordionGroup>

## Full Client Example

The following TypeScript example connects to the market channel, subscribes to a token with an initial book dump, handles all event types, and reconnects automatically with exponential backoff.

```typescript TypeScript
const ws = new WebSocket('wss://ws-subscriptions-clob.calibri.com/ws/market');

ws.onopen = () => {
  ws.send(JSON.stringify({
    type: 'market',
    assets_ids: ['71321045679252212594626385532706912750332728571942532289631379312455583992563'],
    initial_dump: true,
  }));
};

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  switch (msg.event_type) {
    case 'book':
      console.log(`Book: ${msg.bids.length} bids, ${msg.asks.length} asks`);
      break;
    case 'price_change':
      console.log(`Price update: ${msg.price} (${msg.side})`);
      break;
    case 'last_trade_price':
      console.log(`Last trade: ${msg.price} — tx ${msg.transaction_hash}`);
      break;
    case 'tick_size_change':
      console.log(`New tick size: ${msg.new_tick_size}`);
      break;
    case 'market_resolved':
      console.log(`Market resolved: ${msg.outcome}`);
      break;
    default:
      console.log('Unknown event:', msg);
  }
};

ws.onerror = (err) => {
  console.error('WebSocket error:', err);
};

// Reconnect with exponential backoff
function connectWithBackoff(delay = 1000) {
  const ws = new WebSocket('wss://ws-subscriptions-clob.calibri.com/ws/market');
  ws.onclose = () => setTimeout(() => connectWithBackoff(Math.min(delay * 2, 30000)), delay);
  return ws;
}
```

<Warning>
  WebSocket connections can drop due to network interruptions or server-side resets. Always implement reconnection logic with exponential backoff — the example above caps the retry delay at 30 seconds. After reconnecting, re-send your subscription message and request an `initial_dump` to resync your local order book state.
</Warning>
