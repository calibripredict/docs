The user WebSocket channel delivers a private, real-time stream of events scoped to your account. Every time one of your orders changes state — placed, partially filled, cancelled, or fully matched — you receive an `order` event. Every confirmed trade fill produces a `trade` event with the on-chain transaction hash. Using this channel eliminates the need to poll REST endpoints for order status and gives your trading system the lowest possible latency view of your account activity.

---

## Connection

Connect to the authenticated user channel at:

```
wss://ws-subscriptions-clob.calibri.com/ws/user
```

L2 authentication is required. You send your credentials as part of the first message after the connection opens — there are no authentication headers on the WebSocket handshake itself.

---

## Authentication

Immediately after the connection opens, send the following JSON authentication message. The server will not emit any events until it validates your credentials.

```json
{
  "type": "user",
  "auth": {
    "apiKey": "<your-api-key>",
    "secret": "<your-secret>",
    "passphrase": "<your-passphrase>",
    "timestamp": 1700000000,
    "signature": "<l2-signature>"
  }
}
```

### Authentication Fields

<ParamField body="type" type="string" required>
  Must be `"user"`. Identifies this as a user channel authentication message.
</ParamField>

<ParamField body="auth.apiKey" type="string" required>
  Your Calibri API key (`POLY_API_KEY`).
</ParamField>

<ParamField body="auth.secret" type="string" required>
  Your API secret, used to generate the HMAC-SHA256 signature.
</ParamField>

<ParamField body="auth.passphrase" type="string" required>
  Your API passphrase (`POLY_PASSPHRASE`).
</ParamField>

<ParamField body="auth.timestamp" type="number" required>
  Current Unix time in seconds. The server rejects timestamps that are too far from its own clock.
</ParamField>

<ParamField body="auth.signature" type="string" required>
  HMAC-SHA256 signature authenticating this connection request.
</ParamField>

<Note>
  The WebSocket signature uses the same construction as REST L2 signatures. Concatenate the timestamp and the string `GET/auth` as your message (e.g., `1700000000GET/auth`), then sign it with your base64-decoded secret using HMAC-SHA256, and encode the result as base64url without trailing padding. See the TypeScript example below for the full implementation.
</Note>

## Event Types

After successful authentication, the server streams the following event types for your account.

### `order` — Order Status Update

You receive an `order` event whenever the state of one of your orders changes: when it is accepted, partially filled, fully matched, cancelled, or expired.

```json
{
  "event_type": "order",
  "id": "0xOrderId...",
  "status": "MATCHED",
  "tokenId": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "side": "BUY",
  "price": "0.62",
  "originalSize": "200.00",
  "remainingSize": "0.00",
  "timestamp": "1700000100"
}
```

| Field | Type | Description |
|---|---|---|
| `id` | string | Unique order ID. |
| `status` | string | Current order status: `OPEN`, `MATCHED`, `CANCELLED`, `PARTIALLY_FILLED`. |
| `tokenId` | string | The outcome token ID this order is for. |
| `side` | string | `"BUY"` or `"SELL"`. |
| `price` | string | The limit price of the order. |
| `originalSize` | string | The size of the order when it was originally submitted. |
| `remainingSize` | string | The unfilled size remaining. `"0.00"` when fully matched. |
| `timestamp` | string | Unix timestamp (seconds) of this status update. |

---

### `trade` — Trade Fill

You receive a `trade` event for every fill against one of your orders. Each `trade` event corresponds to a single on-chain match and includes the transaction hash for independent verification.

```json
{
  "event_type": "trade",
  "id": "0xTradeId...",
  "taker_order_id": "0xTakerOrderId...",
  "asset_id": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "side": "BUY",
  "price": "0.62",
  "size": "150.00",
  "status": "CONFIRMED",
  "transaction_hash": "0xTxHash...",
  "timestamp": "1700000102"
}
```

| Field | Type | Description |
|---|---|---|
| `id` | string | Unique trade ID. |
| `taker_order_id` | string | The order ID of the taker side of this match. |
| `asset_id` | string | The outcome token ID involved in the trade. |
| `side` | string | `"BUY"` or `"SELL"` from your perspective. |
| `price` | string | The price at which the trade executed. |
| `size` | string | The number of shares filled in this trade. |
| `status` | string | Trade confirmation status (e.g., `"CONFIRMED"`). |
| `transaction_hash` | string | The on-chain transaction hash of the matched trade. |
| `timestamp` | string | Unix timestamp (seconds) of the fill. |

## Full TypeScript Example

The following example shows how to build the L2 WebSocket signature, open the user channel, authenticate, and handle order and trade events.

```typescript TypeScript
import crypto from 'crypto';

function buildWsSignature(secret: string, timestamp: number): string {
  const message = `${timestamp}GET/auth`;
  const key = Buffer.from(secret, 'base64');
  return crypto
    .createHmac('sha256', key)
    .update(message)
    .digest('base64url')
    .replace(/=+$/, '');
}

const apiKey = process.env.POLY_API_KEY!;
const secret = process.env.POLY_SECRET!;
const passphrase = process.env.POLY_PASSPHRASE!;

const timestamp = Math.floor(Date.now() / 1000);
const signature = buildWsSignature(secret, timestamp);

const ws = new WebSocket('wss://ws-subscriptions-clob.calibri.com/ws/user');

ws.onopen = () => {
  ws.send(JSON.stringify({
    type: 'user',
    auth: {
      apiKey,
      secret,
      passphrase,
      timestamp,
      signature,
    },
  }));
};

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.event_type === 'order') {
    console.log(`Order ${msg.id}: ${msg.status} (remaining: ${msg.remainingSize})`);
  } else if (msg.event_type === 'trade') {
    console.log(`Trade filled: ${msg.size} @ ${msg.price} — tx ${msg.transaction_hash}`);
  }
};

ws.onerror = (err) => {
  console.error('WebSocket error:', err);
};
```

<Tip>
  Run the user channel alongside the market channel in the same application to build a complete real-time trading loop. Use market channel `price_change` events to track the order book and trigger order submissions, then use user channel `order` and `trade` events to track the lifecycle of those orders — all without polling any REST endpoints.
</Tip>

<Warning>
  The user channel connection will drop periodically due to network conditions or server-side keepalive timeouts. Implement reconnection logic with exponential backoff, and re-send the full authentication message every time you reconnect — the server does not persist your session across connections. Generate a fresh `timestamp` and `signature` on each reconnect attempt.
</Warning>
