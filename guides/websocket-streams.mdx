Calibri's WebSocket API gives you a persistent, low-latency connection to live market data and account events. Instead of polling REST endpoints, you subscribe once and receive a continuous stream of order book snapshots, price changes, trade fills, and order status updates as they happen. This guide walks you through connecting to both the public market channel and the authenticated user channel.

## Available Channels

| Channel | URL | Auth Required | Description |
|---|---|---|---|
| Market | `wss://ws-subscriptions-clob.calibri.com/ws/market` | No | Order book snapshots, price changes, trade events, market resolution |
| User | `wss://ws-subscriptions-clob.calibri.com/ws/user` | Yes (L2) | Order status updates, trade fills for your account |

## Connect to the Market Channel

<Steps>

<Step title="Open the WebSocket connection">
  Connect to the market channel endpoint. No authentication headers are required.

  ```typescript
  const ws = new WebSocket('wss://ws-subscriptions-clob.calibri.com/ws/market');
  ```
</Step>

<Step title="Send a subscription message">
  Once the connection is open, send a JSON subscription message specifying the outcome token IDs you want to track. You can include multiple token IDs in a single subscription.

  ```json
  {
    "type": "market",
    "assets_ids": [
      "71321045679252212594626385532706912750332728571942532289631379312455583992563"
    ],
    "initial_dump": true
  }
  ```

  Setting `initial_dump: true` instructs the server to immediately send a full order book snapshot for each subscribed token before streaming incremental updates.
</Step>

<Step title="Receive the initial snapshot">
  If you requested `initial_dump: true`, the first message for each token is a `book` event containing the complete order book state. Use this to initialise your local book before applying incremental updates.

  ```json
  {
    "event_type": "book",
    "token": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
    "bids": [
      { "price": "0.64", "size": "500" },
      { "price": "0.63", "size": "1200" }
    ],
    "asks": [
      { "price": "0.66", "size": "300" },
      { "price": "0.67", "size": "800" }
    ],
    "hash": "0xf3a2...",
    "timestamp": "1712000100000",
    "tick_size": "0.01",
    "min_order_size": "5"
  }
  ```
</Step>

<Step title="Handle incoming events">
  After the initial snapshot, the server pushes incremental events as market conditions change. Parse each message by its `event_type` field and update your local state accordingly.

  ```typescript
  ws.onmessage = (event) => {
    const data = JSON.parse(event.data);

    switch (data.event_type) {
      case 'book':
        // Full order book snapshot — reinitialise local book
        break;
      case 'price_change':
        // Incremental price update
        break;
      case 'last_trade_price':
        // Most recent trade execution
        break;
      case 'tick_size_change':
        // Minimum price increment has changed
        break;
      case 'market_resolved':
        // Market has resolved — close your positions
        break;
    }
  };
  ```
</Step>

</Steps>

## Market Channel Events

<AccordionGroup>

<Accordion title="book — Full order book snapshot">
  Sent on initial connection (if `initial_dump: true`) and periodically as a consistency checkpoint. Replace your local order book entirely when you receive this event.

  ```json
  {
    "event_type": "book",
    "token": "<token_id>",
    "bids": [{ "price": "0.64", "size": "500" }],
    "asks": [{ "price": "0.66", "size": "300" }],
    "hash": "0xf3a2...",
    "timestamp": "1712000100000",
    "tick_size": "0.01",
    "min_order_size": "5"
  }
  ```
</Accordion>

<Accordion title="price_change — Incremental price update">
  Sent whenever a new order is placed or cancelled that changes the inside quote or book depth. Update only the affected price level in your local book.

  ```json
  {
    "event_type": "price_change",
    "token": "<token_id>",
    "price": "0.65",
    "size": "200",
    "side": "BUY",
    "bestBid": "0.65",
    "bestAsk": "0.66"
  }
  ```

  A `size` of `"0"` means the level has been removed from the book entirely.
</Accordion>

<Accordion title="last_trade_price — Most recent execution">
  Fired after each on-chain trade settlement. Includes the transaction hash for independent verification.

  ```json
  {
    "event_type": "last_trade_price",
    "token": "<token_id>",
    "price": "0.65",
    "size": "100",
    "side": "BUY",
    "transactionHash": "0xabc123..."
  }
  ```
</Accordion>

<Accordion title="tick_size_change — Minimum increment update">
  Calibri may adjust the minimum price increment for a market. Update your quoting logic when you receive this event — orders at invalid price levels will be rejected.

  ```json
  {
    "event_type": "tick_size_change",
    "token": "<token_id>",
    "old_tick_size": "0.01",
    "new_tick_size": "0.001"
  }
  ```
</Accordion>

<Accordion title="market_resolved — Resolution notification">
  Sent when the oracle resolves the market. Includes the winning outcome index. After this event, no new orders can be placed; you can redeem winning tokens via the relayer.

  ```json
  {
    "event_type": "market_resolved",
    "conditionId": "0x3d4e...",
    "winningOutcomeIndex": 0,
    "resolvedAt": "1712086400000"
  }
  ```
</Accordion>

</AccordionGroup>

## Connect to the User Channel

The user channel delivers private, account-scoped events. You must authenticate with your L2 credentials in the initial message immediately after the connection opens.

```bash
wss://ws-subscriptions-clob.calibri.com/ws/user
```

Send the authentication message as the first payload:

```json
{
  "type": "user",
  "auth": {
    "apiKey": "your-api-key-uuid",
    "secret": "your-secret",
    "passphrase": "your-passphrase",
    "timestamp": "1712000000"
  }
}
```

After a successful authentication acknowledgement, you will receive a stream of order and trade events scoped to your account.

---

## User Channel Events

**`order` — Order status update**

Fires whenever one of your orders changes state: submitted, partially filled, fully filled, cancelled, or expired.

```json
{
  "event_type": "order",
  "orderId": "0xd7f3a...",
  "status": "matched",
  "tokenId": "<token_id>",
  "side": "BUY",
  "price": "0.65",
  "originalSize": "100",
  "remainingSize": "0",
  "updatedAt": "1712000150000"
}
```

**`trade` — Trade fill**

Fires when one of your orders fills — either partially or fully — confirming execution price and size.

```json
{
  "event_type": "trade",
  "tradeId": "0xabc...",
  "orderId": "0xd7f3a...",
  "tokenId": "<token_id>",
  "side": "BUY",
  "price": "0.65",
  "size": "100",
  "role": "maker",
  "timestamp": "1712000150000"
}
```

## Full TypeScript Examples

### Market Channel

The example below connects to the market channel, requests an initial order book dump, and logs price change events:

```typescript
const ws = new WebSocket('wss://ws-subscriptions-clob.calibri.com/ws/market');

ws.onopen = () => {
  ws.send(JSON.stringify({
    type: 'market',
    assets_ids: ['71321045679252212594626385532706912750332728571942532289631379312455583992563'],
    initial_dump: true,
  }));
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);

  if (data.event_type === 'price_change') {
    console.log(`Price: ${data.price}, Best bid: ${data.bestBid}, Best ask: ${data.bestAsk}`);
  }
};

ws.onerror = (error) => {
  console.error('WebSocket error:', error);
};

ws.onclose = (event) => {
  console.warn(`Connection closed (code ${event.code}) — reconnecting...`);
  // Implement reconnection logic here
};
```

### User Channel

The example below connects to the authenticated user channel and logs order and trade events for your account. Replace the credentials with your actual API key, secret, and passphrase.

```typescript
const wsUser = new WebSocket('wss://ws-subscriptions-clob.calibri.com/ws/user');

wsUser.onopen = () => {
  // Send authentication as the very first message
  wsUser.send(JSON.stringify({
    type: 'user',
    auth: {
      apiKey: process.env.POLY_API_KEY,
      secret: process.env.POLY_SECRET,
      passphrase: process.env.POLY_PASSPHRASE,
      timestamp: Math.floor(Date.now() / 1000).toString(),
    },
  }));
};

wsUser.onmessage = (event) => {
  const data = JSON.parse(event.data);

  switch (data.event_type) {
    case 'order':
      console.log(`Order ${data.orderId} status: ${data.status}, remaining: ${data.remainingSize}`);
      break;
    case 'trade':
      console.log(`Trade filled — price: ${data.price}, size: ${data.size}, role: ${data.role}`);
      break;
    default:
      console.log('User event:', data);
  }
};

wsUser.onerror = (error) => {
  console.error('User channel error:', error);
};

wsUser.onclose = (event) => {
  console.warn(`User channel closed (code ${event.code}) — reconnecting...`);
  // Implement reconnection logic here
};
```

---

<Note>
  WebSocket connections can drop due to network interruptions or server-side maintenance. Implement **exponential backoff** in your reconnection logic — for example, wait 1 s, then 2 s, then 4 s between attempts, up to a maximum of 60 s. After reconnecting, always request `initial_dump: true` to resynchronise your local order book state.
</Note>

<Tip>
  You can subscribe to multiple markets in a **single WebSocket connection** by including multiple token IDs in the `assets_ids` array. This is more efficient than opening a separate connection per market and reduces the risk of hitting connection limits.

  ```json
  {
    "type": "market",
    "assets_ids": [
      "71321045679252212594626385532706912750332728571942532289631379312455583992563",
      "52114319501245915516055106046884209969926127482827954674443846427813813222426"
    ],
    "initial_dump": true
  }
  ```
</Tip>
