Calibri's Central Limit Order Book (CLOB) lets you trade outcome tokens on any active prediction market. You construct and EIP-712 sign your orders locally, then submit them to Calibri's trading API — the exchange never holds your private key. This guide walks you through selecting a market, building an order, submitting it, and managing its lifecycle.

## Prerequisites

Before you place your first order, make sure you have the following ready:

- **API credentials** — an API key, passphrase, and signing key from the Calibri dashboard. See the [Authentication guide](/authentication) for setup instructions.
- **pUSD balance** — funds deposited and available in your trading account. Check your current balance via the [balances endpoint](/api-reference/account/balances).

---

## Step 1: Choose Your Market and Token ID

Every market on Calibri has two outcome tokens — one for **Yes** and one for **No**. You need the `tokenId` of the specific outcome you want to trade.

Fetch the list of active markets from the Gamma API:

```bash
GET https://gamma-api.calibri.com/markets
```

Each market object contains a `clobTokenIds` array with exactly two entries — index `0` is the Yes token and index `1` is the No token:

```json
{
  "conditionId": "0x3d4e...",
  "question": "Will ETH exceed $5,000 before December 31?",
  "clobTokenIds": [
    "71321045679252212594626385532706912750332728571942532289631379312455583992563",
    "52114319501245915516055106046884209969926127482827954674443846427813813222426"
  ],
  "active": true,
  "closed": false
}
```

Copy the `tokenId` for the outcome you want to trade — you'll use it in the next step.

## Step 2: Build and Sign the Order

Calibri orders are [EIP-712](https://eips.ethereum.org/EIPS/eip-712) signed messages. The signature proves you authorised the trade without exposing your private key. The official SDKs handle domain separation, struct hashing, and signing automatically.

<CodeGroup>

```typescript TypeScript
import { createSecureClient, OrderSide, OrderType } from '@calibri/client';

const client = createSecureClient({
  apiKey,
  secret,
  passphrase,
  address, // your wallet address
});

// Build a signed GTC limit order to buy 100 shares at $0.65
const order = await client.placeLimitOrder({
  tokenId: '71321045679252212594626385532706912750332728571942532289631379312455583992563',
  side: OrderSide.BUY,
  price: 0.65,
  size: 100,
  orderType: OrderType.GTC,
});

console.log(order.status); // 'live' | 'matched'
```

```python Python
from calibri import AsyncSecureClient, OrderSide, OrderType

client = AsyncSecureClient(
    api_key=api_key,
    secret=secret,
    passphrase=passphrase,
    address=address,  # your wallet address
)

# Build a signed GTC limit order to buy 100 shares at $0.65
order = await client.place_limit_order(
    token_id='71321045679252212594626385532706912750332728571942532289631379312455583992563',
    side=OrderSide.BUY,
    price=0.65,
    size=100,
    order_type=OrderType.GTC,
)

print(order.status)  # 'live' | 'matched'
```

</CodeGroup>

If you prefer to construct the raw order object yourself, here is the full structure before signing:

```json
{
  "maker": "0xYourWalletAddress",
  "signer": "0xYourSignerAddress",
  "tokenId": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "makerAmount": "65000000",
  "takerAmount": "100000000",
  "side": "BUY",
  "expiration": "0",
  "timestamp": "1712000000000",
  "salt": "84543234532",
  "signatureType": 0
}
```

<Tip>
  Set `expiration` to `0` for Good-Till-Cancelled orders. For time-bound orders, use a Unix timestamp in seconds. Pair this with `orderType: "GTD"` to automatically cancel the order once the deadline passes — useful for event-driven strategies where stale resting orders create unwanted exposure.
</Tip>

## Step 3: Submit the Order

Send the signed order to the CLOB trading API:

```bash
POST https://clob.calibri.com/order
```

**Request headers** (L2 authentication required):

| Header | Description |
|---|---|
| `POLY_ADDRESS` | Your wallet address |
| `POLY_API_KEY` | Your API key UUID |
| `POLY_PASSPHRASE` | Your API passphrase |
| `POLY_SIGNATURE` | Request signature |
| `POLY_TIMESTAMP` | Current Unix timestamp |

**Request body:**

```json
{
  "order": {
    "maker": "0xYourWalletAddress",
    "signer": "0xYourSignerAddress",
    "tokenId": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
    "makerAmount": "65000000",
    "takerAmount": "100000000",
    "side": "BUY",
    "expiration": "0",
    "timestamp": "1712000000000",
    "signature": "0xabc123...",
    "salt": "84543234532",
    "signatureType": 0
  },
  "owner": "your-api-key-uuid",
  "orderType": "GTC",
  "postOnly": false
}
```

**Successful response:**

```json
{
  "status": "live",
  "orderId": "0xd7f3a...",
  "transactionHashes": [],
  "tradeIDs": [],
  "makingAmount": "65000000",
  "takingAmount": "100000000"
}
```

| Status | Meaning |
|---|---|
| `live` | The order is resting on the book, waiting for a match. |
| `matched` | The order fully or partially filled immediately upon submission. |
| `delayed` | The order was accepted but is pending on-chain confirmation. |

<Warning>
  **FOK (Fill-or-Kill) orders are rejected — not partially filled — if the full size cannot be matched immediately.** Do not rely on partial fills from FOK orders. Use `FAK` (Fill-and-Kill) if you want to fill whatever is available and cancel the remainder.
</Warning>

## Step 4: Monitor Order Status

Poll the order status at any time using its `orderId`:

```bash
GET https://clob.calibri.com/data/order/{orderId}
```

**Response:**

```json
{
  "id": "0xd7f3a...",
  "status": "live",
  "tokenId": "71321045679252212594626385532706912750332728571942532289631379312455583992563",
  "side": "BUY",
  "price": "0.65",
  "originalSize": "100",
  "remainingSize": "100",
  "createdAt": "2024-04-01T12:00:00Z"
}
```

To list all open orders for a market or wallet, use the query endpoint:

```bash
GET https://clob.calibri.com/data/orders?market=0x3d4e...&owner=your-api-key-uuid
```

Supported query parameters:

| Parameter | Description |
|---|---|
| `market` | Filter by `conditionId` |
| `asset_id` | Filter by outcome token ID |
| `owner` | Filter by API key UUID |

## Cancel Orders

### Cancel a Single Order

```bash
DELETE https://clob.calibri.com/order/{orderId}
```

### Cancel Multiple Orders

```bash
DELETE https://clob.calibri.com/orders
```

```json
{
  "ids": ["0xd7f3a...", "0xe8c4b..."]
}
```

### Cancel All Orders for a Market

```bash
DELETE https://clob.calibri.com/orders/market
```

```json
{
  "market": "0x3d4e..."
}
```

### Cancel All Open Orders

```bash
DELETE https://clob.calibri.com/orders/all
```

This cancels every open order across all markets for your account. Use this for emergency risk management or when shutting down a trading session.

## Batch Orders

You can submit up to **15 orders** in a single request to reduce round-trip latency:

```bash
POST https://clob.calibri.com/orders
```

```json
{
  "orders": [
    { "order": { ... }, "owner": "...", "orderType": "GTC" },
    { "order": { ... }, "owner": "...", "orderType": "GTC" }
  ]
}
```

Each entry in the response array corresponds to the order at the same index in the request, giving you per-order status and IDs in one call.
